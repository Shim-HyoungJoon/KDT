AI 시대의 개발 패러다임

1. AI가 바꾼 개발 패러다임
    1) Human-Centric Coding
        - 개발자가 모든 코드를 직접 작성
        - 문서/레퍼런스 기반 문제 해결
        - 반복적 패턴이 많고, 생산성의 한계 존재
        - 개발 난이도 = 구현 난이도

    2) AI-First Coding
        - 코드 생산은 AI가 대부분 처리
        - 개발자는 방향/설계/품질 관리를 담당
        - 문제 해결 속도가 10배 이상 빨라짐
        - 개발 난이도 = 문제 정의 난이도로 이동

2. AI 시대 개발자의 역할
    1) 문제 정의자
        - AI는 문제를 풀어주지만, 문제를 정의하는 건 인간이 할 수 있음
        - 어떤 기능인가? 어떤 제약이 있는가? 어떤 기술 스택인가?
        - 이를 정확하게 전달해야 AI가 올바르게 움직이는가

    2) 설계자
        - AI는 코드를 잘 만들지만, 시스템 전체 구조는 결정 못함
        - 데이터 모델, API구성, 라우팅 전략, 보안 구조는 인간이 설계

    3) 품질 관리자
        - AI가 만든 코드는 겉으로는 완벽해 보이지만, 내부가 허술한 경우가 많음
        - 보안 취약점, 에러 처리 미흡, 불필요한 복잡성 검증 필요
        - 코드를 작성하는 능력보다 검증하는 능력이 더 중요

    4) 커뮤니케이터
        - 프롬프트는 이제 새로운 개발 언어
        - 과거: JavaScript, Python이 개발 언어
        - 현재: 자연어 자체가 개발 언어가 됨

3. 주요 AI 개발 툴
    1) Cursor AI: 코드 자동 생성, 리팩터링, 파일 단위 작업 능력 최고
    2) OpenAI ChatGPT: 개념 설명, 코드 템플릿, 시스템 설계 질의
    3) Replit AI: 브라우저 기반 실시간 코드 생성
    4) GitHub Copilot: IDE 안에서 자동 코드 제안
    5) Claude / Gemini AI: LLM 기반 분석 및 문서 작성
    6) MCP (Model Context Protocol): 개발 워크플로우 자동화의 차세대 기술(Figma/Notion/GitHub 연결)

4. 기존 코딩 vs AI 활용 코딩에서 주의할 점
    - AI가 설계를 무시하고 임의로 작성
    - 예외 처리 부족
    - 보안 취약
    - 불필요하게 복잡한 코드 생성
    - 현재 프로젝트 구조와 불일치

5. 프롬프트 엔지니어링
AI에게 원하는 결과를 가장 정확하고 빠르게 생성하도록 문제를 구조화해 전달하는 기술

    1) 좋은 프롬프트의 핵심 요소
        - 역할: "너는 시니어 FE 개발자야"라고 지정하면 AI의 품질이 달라짐
        - 목표: 무엇을 해결하려는지 명확히 제시
        - 환경: Next.js 16, TypeScript, Supabase 같은 기술 환경 명시
        - 제약조건: Server Component로 작성, TailwindCSS 사용, SEO 고려
        - 출력 형식: 문서인지, 코드인지, 예시인지 명시
        - 예시: 비슷한 코드나 결과물 예시를 제공하면 정확도가 크게 향상

    2) 나쁜 프롬프트
        예: 'next.js 로그인 코드 작성해줘'

        문제점
        - 이메일, 아이디, OAuth
        - DB 구조는?
        - TypeScript 여부?
        > 정보 부족으로 엉뚱한 코드 생성

6. Cursor 설치와 기본 사용법
    1. Cursor
        - VSCode를 기반으로 한 코드 에디터
        - VSCode와 비슷한 에디터 내부에 AI 채팅, 코드 편집, 자동 리팩터링, 패치 생성 기능이 통합되어 있음
        - 여러 LLM 제공자(OpenAI, Anthropic, Google 등)와 연동
    2. Cursor를 잘 쓰기 위한 팁
        - 작업 단위를 잘게 나누기
            * 한 번에 너무 많은 것을 시키기보다, 5분 만에 끝낼 수 있는 작은 단위로 작업을 쪼개서 요청하는 것이 좋음
            * 예) 어드민 페이지를 만들어줘(x), 어드민 리스트 테이블의 헤더만 먼저 만들어줘(o)
        - Rules와 기존 코드 적극 활용
            * User Rules
                - 모든 프로젝트에 전역적으로 적용
                - 개인의 코딩 스타일, 선호사항
                - 항상 함수형 컴포넌트 사용, 주석은 한국어로 작성, 변수명은 camelCase 사용
            * Project Rules
                - 해당 프로젝트에만 적용
                - 프로젝트별 기술 스택
                - NextJS App Router 구조 사용, Tailwind CSS만 사용, styled-components 금지
            * 우선순위: Project Rules > User Rules 프로젝트 규칙이 사용자 규칙보다 우선 적용
            * 팀 협업 시
                - Project Rules: Git에 커밋하여 팀원 전체가 동일한 규칙을 공유
                - User RulesL: 개인 환경에만 존재, 공유 안 됨
            * 권장 사항
                - User Rules에 넣을 것: 개인 코딩 습관, 언어 선어도, 일반적인 베스트 프렉티스
                - Project Rules에 넣을 것: 프로젝트 기술 스택, 제약, 빌드/배포 규칙, 폴더 구조 가이드

> 코드를 반드시 리뷰하고, 작은 수정은 직접 하기
    - AI가 생성한 코드는 초안일 뿐
    - 특히 보안, 마이그레이션 관련 코드는 항상 꼼꼼히 검토
    - 생산성을 높이되, 최종 책임은 항상 개발자에게 있다는 관점을 유지

7. 주요 코드 모델 비교
    1. Claude X Sonnet: 코드 품질 최고. 복잡한 리팩토링에 강함
    2. GPT-X: 범용적, 설명 능력 우수
    3. GPT-Xo: 속도와 성능의 균형
    4. Cursor Small: 빠른 응답, 간단한 작업에 적합
    5. Cursor Auto: 추천, 상황에 맞는 최적의 모델 자동 선택

    Context Length: 긴 파일 작업 시 Long Context 모델 선택
    Temperature: 창의적 작업은 높게, 정확한 코드는 낮게
    Privacy Mode: 민감한 코드베이스 privacy mode 활성화
